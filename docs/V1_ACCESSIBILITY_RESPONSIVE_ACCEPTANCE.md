# V1 Accessibility and Responsive Acceptance

V1 acceptance retains the existing semantic labels, keyboard/focus guards, accessible modal behavior, reduced layout overflow and private error handling. Independent representative in-app Browser evidence covered `1280x720` and exact `390x844`, while automated acceptance retains 1440x900, 1366x768, 1024x768, 768x1024, 375x667 and 320x568. Light/dark themes, login, Release Operations, Parent linked-child/read-only context, Teacher exact-scope behavior, multi-role context separation, Viewer bounded access and privileged-route denial passed.

The first Teacher `/teacher/classwork` probe exposed a production Server Component error when permission existed but no active timetable scope was linked. The page now catches only the expected `TEACHER_SCOPE_MISSING` and `TEACHER_SCOPE_EMPTY` access codes and renders a labelled fail-closed empty state; API and mutation authorization remain unchanged. The rebuilt production runtime passed the same path at desktop and exact `390x844` with no horizontal overflow.

Automated/source checks and the final Browser batch confirmed accessible naming, a visible two-pixel keyboard focus outline, 44 px visible actions, contained mobile cards/tables, no native dialog dependency, no final hydration/console warning or error, no rendered raw IDs and zero page-level horizontal overflow. The PWA manifest, versioned public cache and network-only private/API rules were also inspected. The production runtime was stopped and the viewport override reset before cleanup. Browser evidence is synthetic and local only; assistive-technology certification and public-device fleet support remain separate operational validation.
