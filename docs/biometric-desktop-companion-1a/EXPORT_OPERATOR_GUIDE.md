## Explicit version 1 profile

Start with `apps/nalanda-biometric-bridge/export.config.synthetic.example.json` only for owned synthetic exercises. Its SID, path, IDs and mapping are placeholders; it is not a school configuration. Keep committed examples `transportEnabled=false`, `syntheticOnly=true`. Do not label real exports synthetic. Live configuration requires separate authorization, `syntheticOnly=false` and all gates below; this task does not activate it.

The adapter profile name is `ETIMETRACKLITE_RAW_EXPORT_V1`. `exportInput` declares exactly one absolute local source directory, approved reader/writer SIDs, stale interval, and a profile with:

| Field | Supported contract |
|---|---|
| schemaVersion / profileId | `1` and a management-selected revision identity; canonical SHA256 includes all profile fields and bound ERP device ID |
| columns / header | Exactly Employee Device Code **or** Employee code, Punch DateTime, Device Id, Direction; explicit permutation and exact case-sensitive headers or no header |
| separator / encoding | Comma CSV or tab; strict UTF-8 without BOM or explicitly UTF-8 with BOM. Quoted single-line CSV fields supported; embedded newlines, fixed-width/space/no-separator, ANSI/UTF-16 and binary exports refused |
| filenamePrefix / extensions | Explicit safe prefix and `.csv`, `.txt`; `.dat` only if explicitly added as the same textual profile. No format sniffing. XLS/PDF/Access/SQL unsupported |
| dateFormat / culture | Exact `yyyy-MM-dd HH:mm:ss`, `dd/MM/yyyy HH:mm:ss` or `dd-MMM-yyyy HH:mm:ss`; `en-IN` or `en-GB`, English Jan…Dec for MMM, years 2000–2099. No machine-locale/date guessing |
| timezone | Explicit `Asia/Kolkata` or `UTC`; other zones deferred. Original local string, zone, offset timestamp and UTC interpretation retained privately |
| employeeIdentifierKind | `EmployeeDeviceCode` or `EmployeeCode`; names/surnames never match. Both require an approved one-to-one source-code → canonical device-user mapping and mapping reference. Leading zeroes remain strings |
| localDeviceId | Exact vendor-local ID bound to the outer management-configured device UUID; neither a serial nor ERP UUID may be inferred from a row |
| directionMapping | Explicit case-sensitive string values → IN, OUT or UNKNOWN. Example IN/OUT strings are synthetic. No universal 0/1 convention, alternating inference or direction synthesis |

Host `127.0.0.1`, port `1` in the export device entry are inert compatibility fields, not a device endpoint. This adapter makes no network connection. A source file cannot set endpoints, registration, signing authority or keys. Missing verification method remains OTHER; no fingerprint/template data is read.

## Manual setup and preview

1. On the installed eTimeTrackLite version, an authorized operator first locates **Device logs / Export Device logs in custom format** and records the actual available fields and format settings. Do not use calculated attendance or employee-master exports. Do not change device settings, invoke download/clear/reset/enrollment, or change vendor startup/database configuration under this guide.
2. Choose Employee Device Code if available. If only Employee code is available, use that namespace and obtain an approved exact mapping to the canonical device-user IDs. Confirm vendor-local Device Id separately from the trusted ERP registration UUID. Select the four fields in the configured order, exact date/culture/timezone and explicit direction symbols. Obtain an owner-approved minimal sample before asserting compatibility.
3. Use one dedicated source folder separate from package, config, queue, health and key roots. An administrator should approve existing exporter and service identities and configure source permissions through the established Windows ownership/ACL process. Allow only SYSTEM, Administrators and explicitly approved exporter/reader SIDs; the reader needs read/traverse, exporter needs appropriate write rights. Protect ancestors against unapproved replacement. No Everyone/Users/Authenticated Users access. This adapter only **checks** permissions and never repairs them. It refuses links/reparse points, hardlinked files, unsafe names, network paths and protected-root overlap. Do not use a broadly shared Downloads/Temp folder.
4. Place a management-controlled config outside the source directory. Preview with `pnpm.cmd --dir apps/nalanda-biometric-bridge export:preview <absolute-config.json>` or packaged `node dist/export-preview.js <absolute-config.json>`. It returns profile hash and bounded aggregate validation counts/codes, without staff rows, filenames, raw errors or queue writes. Preview is not mapping, payroll or deployment approval. `config:validate <absolute-config.json>` validates the configured adapter path too.
5. When separately authorized, the existing host runs the existing `dist/agent.js` with that config; its ordinary polling cycle instantiates the file adapter and commits to the existing encrypted queue. There is no second service, watcher daemon or database. This milestone does not install or start a school/MSI service.

## Replay, limits and operator states

The reader enumerates at most 256 immediate directory entries, processes at most eight files per poll and at most 8 MiB of snapshot reads (both full reads count). Each file is at most 2 MiB, 20,000 rows and 2,048 bytes per line. A record must end in newline. Two complete reads plus handle/path identity and size/change-time checks detect modification, truncation or replacement; an incomplete/unstable file is deferred without consuming its rows. Nothing writes, locks exclusively, renames, deletes or adds receipts beside vendor files.

Queue events and source identity/checkpoint/provenance commit together in the existing AES-GCM atomic file. On restart, a pre-commit interruption replays, and a post-commit interruption finds the same committed byte receipt. Byte-identical renamed files are replayed once. A verified same-incarnation append prefix is skipped while its tail is processed. New older punches are not filtered by a timestamp cursor. Re-exported/reordered/overlapping observations without trustworthy vendor event IDs are conservatively retained as review observations; same-second punches are never silently collapsed. `export-v1-*` and `export-review-*` are **bridge observation references**, not invented hardware event IDs. Conflicts can hold an unsent earlier event and its existing batch; transport Resume cannot release a source-semantic hold. Resolving these observations requires a separately reviewed management disposition, not automatic payroll or speculative direction assignment.

Malformed rows retain line/hash/error accounting inside the encrypted queue. Whole-file format/size/access refusals retain bounded private source-key/error metadata; row totals are **unknown** when the file could not safely be parsed, not reported as zero rejected staff records. Scan progress moves past permanent file errors so later valid files can be processed; refused sources remain unchanged for correction and preview. Metadata is bounded (4,096 file receipts, 256 source checkpoints/refusals, 100,000 observations/subjects, existing queue capacity). Capacity or disk failure holds collection without committing new source rows. Do not delete queue state to make space or purge receipts as routine cleanup; seek a reviewed archival/disposition procedure.

Health separates WAITING_NO_FILES, READING/deferred write, STALE_SOURCE, PROFILE_MISMATCH, REVIEW_REQUIRED, QUEUE_HELD, HEALTHY_INGESTION and SOURCE_UNAVAILABLE. Freshness measures committed new export bytes, not K30 reachability or staff presence. Re-reading unchanged bytes does not refresh it; filename/mtime/download time is never a punch timestamp. Queue-held and source state do not approve business attendance. General health contains aggregate counts/codes only; private queue data remains protected. No logs of staff rows.
