# Admissions Operator Guide

Use `/admission-crm` only with the active authorised role. Record the minimum enquiry, mask contacts in shared views, and append follow-ups or visits with factual bounded notes. Issue an application invitation only after the cycle and purpose are confirmed. The one-time token is shown for authorised manual copy/local QA only; do not paste it into logs or public notes.

Before an offer or conversion, check completeness, encrypted document recovery, assigned reviews and every duplicate suggestion. Record a specific decision reason. Conversion preview must confirm exactly one Student/enrollment, optional pending Parent IAM account and the explicit list of excluded records.

Use `/admission-crm/reports` for aggregate funnel/export. Viewer values below the minimum group size are suppressed. The retention page is preview-only. Never promise statutory recognition, admission certainty, fee acceptance or message delivery from this module.

Incident response: stop the workflow on token disclosure, wrong-family visibility, document integrity failure, unresolved duplicates, unexpected fee/location rows, stale-version conflicts or conversion ambiguity. Preserve evidence and escalate to Director/Super Admin; do not repair by direct database editing.
