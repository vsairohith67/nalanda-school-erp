# Library Data Model Plan

## Scope and design rules

This is a future-model contract, not a Prisma schema or migration. Use separate circulation entities rather than `BookCatalogItem` and book-sale receipt lines. All durable entities need created/updated timestamps, actor references where relevant, indexed foreign keys, restrictive deletion behavior, safe serializers, and backup/restore coverage in the phase that adds them. Monetary values use `Prisma.Decimal`; dates use the established India-local parsing/presentation conventions.

## Proposed models

| Model | Purpose and important fields | Constraints, relations, and history |
|---|---|---|
| `LibraryTitle` | Bibliographic record: title, subtitle, normalized authors, ISBN, edition, publisher text, publication year, language, subject, category, classification number, default shelf code, description, status. | Index normalized title/ISBN/author/subject. ISBN is not globally unique because editions/legacy data can conflict; use duplicate review. Has many copies and policy/category references. Retire/inactivate rather than delete after a copy exists. Catalog write requires `MANAGE_LIBRARY_CATALOG`. |
| `LibraryCopy` | Physical owned copy: `titleId`, immutable unique `accessionNumber`, optional unique normalized barcode/RFID tag, acquisition date/type (`PURCHASED`, `DONATED`, `TRANSFERRED`, `OTHER`), optional Decimal acquisition cost, optional `vendorId`, optional `expenseRecordId` or invoice snapshot, condition, circulation status, shelf/location, notes, withdrawal date/reason, and optional `replacedByCopyId`. | One title to many copies. Unique non-null accession/barcode/RFID; trim/case-normalize identifiers before validation. `replacedByCopyId` points to a newly accessioned successor and may never reuse the original accession number. Links to loans, reservations through title/copy policy, events, and stock records. Accessioned copies never hard delete. An optional `ExpenseRecord` link is provenance only, must be restricted and reviewed against the chosen vendor/invoice, and creates no expense/payment. Copy write requires `MANAGE_LIBRARY_COPIES`. |
| `LibraryMember` | Membership code, optional `studentId`, optional `staffMemberId`, type, status, joined date, suspension date/reason, notes. | Exactly one linked person: use both server validation and a migration-managed database `CHECK` that one, and only one, FK is non-null. Add separate unique constraints on each non-null FK so a Student or StaffMember has one membership record, not merely one active record. Has loans/reservations/charges. No external type in first implementation. Membership changes require `MANAGE_LIBRARY_MEMBERS`; self-service reads are scoped to the linked authenticated account. |
| `LibraryLoan` | Copy/member, issue date, due date, returned date, status, renew count, issued/returned actor, notes, policy snapshot/version, and nullable `activeCopyKey`. | A copy has at most one open loan. While a loan is open (`ISSUED` or `OVERDUE`), set `activeCopyKey = copyId`; clear it only in the same transaction that closes the loan. A unique constraint on nullable `activeCopyKey` (SQLite allows multiple nulls), plus the transaction/status guard, makes concurrent double issue impossible. Relations to copy/member/events/charges. Closing fields are append-only or compensating-event controlled; never silently edit final returned/lost records. Issue/return permissions are separate. |
| `LibraryReservation` | Title/member and optional allocated copy, requested/expires/fulfilled/cancelled dates, queue position or deterministic ordering, status, actor/reason. | Prevent duplicate active reservation for same member/title; transactionally allocate only an eligible available copy. Preserve cancellation/expiry. Requires `MANAGE_LIBRARY_RESERVATIONS`, with own-member self-service narrowly scoped later. |
| `LibraryCharge` | Loan/copy/member, type, assessed amount, waived amount, paid/settled amount/status, assessment basis, replacement credit, linked misc receipt reference later, approval and reason. | Decimal sums must reconcile; one active assessment per underlying incident/type. Financial collection is separate and links once to Miscellaneous Income receipt after payment. Waiver is immutable/audited and requires `WAIVE_LIBRARY_CHARGES`; Accountant gets only necessary read status. |
| `LibraryCirculationEvent` / `LibraryAuditEvent` | Append-only event: entity type/id, action, before/after safe JSON, reason, actor, timestamp, correlation id. | Index entity/time and actor/time. No password hashes, raw secrets, or unredacted sensitive payloads. Every issue/return/renew/reserve/lost/damaged/charge/waiver/correction records one. Restricted viewers receive a masked projection. |
| `LibraryPolicy` | Effective dates, member/category scope, loan period, maximum loans/renewals, reservation hold, overdue formula, lost/damage rule, required approval settings, status. | Avoid overlapping active policies for the same scope/effective period; deterministic precedence. Preserve policy snapshot at issue/charge. Only `MANAGE_LIBRARY_POLICIES`; school-calendar references are future-only. |
| `LibraryStockVerificationSession` | Session code, scope/shelf, cut-off timestamp, started/finalized dates, expected count snapshot, status, operator/reviewer, notes. | One session owns many records; finalized session immutable other than documented correction/reopen approval. Requires `RUN_LIBRARY_STOCK_VERIFICATION`. |
| `LibraryStockVerificationRecord` | Session/copy, expected vs observed result, scan/manual method, condition, discrepancy/reason, observer/reviewer, timestamps. | Unique session/copy. Do not auto-change a copy to missing/withdrawn; a separate audited decision is required. Restricted reports show aggregates where borrower linkage is unnecessary. |

## Enum and integrity notes

Use explicit enumerations or strictly validated strings for acquisition type, member type/status, condition, copy status, loan status, reservation status, charge type/status, and stock-session/record states. Keep title status distinct from copy circulation status. The loan is canonical for `OVERDUE`; a copy's effective displayed overdue state derives from its single open loan, rather than a separately mutable flag. `REPLACED` retains the original copy and points to a newly accessioned copy; it must not overwrite the previous record. `WITHDRAWN` needs a write-off reason/date and may not bypass an open-loan resolution; `MISSING` needs an investigation/audit trail.

Relationships to `Student`, `StaffMember`, `User`, `Vendor`, and `ExpenseRecord` must use restrict/set-null behavior deliberately so historical circulation remains durable if a related account is deactivated. Never cascade-delete library history from a Student, StaffMember, User, Vendor, or title. Circulation/audit rows are append-only at the application/API boundary, with no hard-delete action; corrections append a compensating event. A new physical-copy row is not an expense, payment, sale, cash movement, or inventory valuation record.

## Backup and restore contract

Each backup version must add only the library arrays introduced in its implementation phase and keep all older backups valid. Restore order is titles, copies, events for Prompt 16F; future phases may add members, policies, loans, reservations, charges, stock sessions, and stock records in dependency order. Follow existing exact-identity collision isolation and idempotence rules, preserve local-newer records, and exclude password hashes.

## Prompt 16F implemented subset

`LibraryTitle`, `LibraryCopy`, and `LibraryCopyEvent` are now live. The implemented title model uses a unique normalized `titleCode` and unique normalized non-null ISBN; the safe exception policy is to correct/inactivate the existing title rather than create an ambiguous duplicate. A copy has a unique immutable accession number, optional unique barcode storage, optional exact Vendor/Expense references, Decimal acquisition cost, current condition/status/shelf, and withdrawal evidence. Every copy starts with `ACCESSIONED`; corrections and state changes append events. No library entity has a hard-delete API.

Backup version 19 added the catalog arrays. Prompt 16G now implements `LibraryMember`, `LibraryPolicy`, `LibraryLoan`, `LibraryReservation`, and append-only `LibraryLoanEvent`; backup version 20 adds their arrays while preserving older backups. `activeCopyKey` prevents two issued loans per copy, `activeMemberTitleKey` prevents duplicate waiting member/title reservations, policy terms are snapshotted, and overdue remains derived. Charge, RFID, and stock models remain future-only.
## Prompt 16H implemented model

`LibraryIncident`, `LibraryChargeRule`, `LibraryCharge`, and append-only `LibraryChargeEvent` are now implemented. Nullable unique active keys enforce one unresolved loan/copy incident and one active overdue charge per loan. Charge rows snapshot rule/rate/amount guidance and have a unique optional Miscellaneous Income receipt link. Terminal incident/charge states are immutable through normal APIs. Backup version 21 validates canonical links, ownership, replacement copies, receipt identity, collisions, exact amounts, and event parents.
