# Real Data Onboarding Precheck

This is a future checklist. Do not import real data under this task.

## Source control

- [ ] Named owner for Student, Guardian and Staff source files.
- [ ] Provenance, collection purpose, date, academic year and authoritative-system reference recorded.
- [ ] Secure transfer/storage location approved; files are absent from Git, public links and ordinary chat.
- [ ] Required fields mapped; unsupported/sensitive fields explicitly excluded or separately approved.
- [ ] Aadhaar/PEN/APAAR, identity documents, photographs, health/safeguarding and payroll data have dedicated authorization or remain excluded.

## Dry run

- [ ] Fresh approved staging/copy, pre-import backup and exact source hash.
- [ ] Template/version match, row bounds, formulas/macros blocked and validation report retained.
- [ ] Duplicate Student/Guardian/Staff rules reviewed by named business owners.
- [ ] Class/section/year, sibling links, inactive/transferred status and unsupported values reconciled.
- [ ] No user account or notification destination is activated by import.

## Approval and rollback

- [ ] Dry-run counts/errors accepted; unresolved rows remain unexecuted.
- [ ] Import plan/version revalidated immediately before execution.
- [ ] Named approver and maintenance window recorded.
- [ ] Post-import counts/samples/finance opening state verified without exposing broad personal data.
- [ ] Rollback scope and dependency consequences understood and rehearsed.
- [ ] Backup restored and access revoked if acceptance fails.
