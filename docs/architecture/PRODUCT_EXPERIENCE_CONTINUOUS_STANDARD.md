# Product Experience continuous standard

Role arrays are non-exhaustive planning hints until server guards and effective account permissions are verified. Confirmed source corrections record Teacher Analytics leadership defaults, aggregate-only Viewer reports, and Director Technical Operations summaries. These source defaults are not current account-access or browser evidence; the inherited screen register remains unchanged.

The visual direction remains premium, restrained, modern and calm: clear hierarchy, deliberate whitespace, readable typography, restrained colour, consistent components and predictable controls. No Apple assets, trademarks or page designs are copied. `NALANDA PUBLIC SCHOOL` remains Georgia Bold in every generated document or image; unsupported font substitution must fail the relevant document acceptance gate.

The audit read the current 363-screen source inventory, shared `app/product-experience.css`, loading/error components, runtime enhancement, historical bugs/backlog, Product Experience architecture and its regression contract. The machine debt register records all 363 source routes with inherited roles and nineteen review dimensions. An inherited shared-style assertion is not a current per-route Browser/accessibility pass. This UX audit performs no current Browser certification of pixels, focus traversal or console behavior; isolated synthetic CI fixtures remain regression evidence only. Unverified dimensions are explicit debt, not invented defects or passes. No Critical accessibility/security defect was directly demonstrated requiring a product-code correction.

Every owning future bundle must cover its changed routes and denied roles on desktop and narrow mobile, light/dark, keyboard and reduced-motion modes. Check information hierarchy, contrast, typography, spacing, target sizes, focus visibility/order/return, motion suppression, loading, empty, error, permission-denied, disabled-feature and offline/degraded states, destructive confirmation, long content, horizontal overflow and hydration/console errors. Use synthetic identities and records only. Include long translated labels and zoom; preserve task context after error. Prefer clear in-app confirmations that name the action and consequence.

Use WCAG AA criteria as an acceptance target with explicit evidence, not a blanket legal-compliance claim: text contrast at least 4.5:1 (3:1 for qualifying large text), visible keyboard focus, meaningful labels, semantic landmarks and accessible errors. Aim for 44 CSS-pixel important touch controls. Respect `prefers-reduced-motion`. Tables need bounded overflow and readable headers; do not force the entire page sideways. Unknown values remain unknown. Separate a blocked provider from a broken core workflow and offer a permitted next action.

Update `config/product-experience-debt-register.json` in place. Each demonstrated defect needs route, actual role, viewport/theme/state, reproduction, severity, owning requirement/bundle, fix evidence and regression result. A routine feature change includes its own UI debt and relevant shared-component checks. Whole-product redesign is not implied. Maintain the screen inventory as routes change, and preserve older evidence dates rather than presenting them as fresh checks.

Later external tools do not belong in school-user flows. Technical Operations can expose an aggregate diagnostic state, while restricted operator runbooks contain deployment/provider details. School users should receive plain descriptions of what happened, what is safe to do next and whether their action completed.

Official acceptance references: [WCAG 2.2 minimum text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) and [enhanced target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html). The 44-pixel aim is an enhanced target, not a claim that every such target is mandated at AA.
