# Technical Incident Response Runbook

1. Classify severity and create the incident from the alert where possible.
2. Assign an owner and record privacy-safe timestamps, observations, and mitigation.
3. Preserve evidence before changes; never include personal data, secrets, raw paths, stack traces, or provider bodies.
4. Use maintenance only for exact non-protected checks.
5. Resolve after the monitored condition recovers and verification passes.
6. Close only with a privacy-safe post-incident summary and follow-up action.
