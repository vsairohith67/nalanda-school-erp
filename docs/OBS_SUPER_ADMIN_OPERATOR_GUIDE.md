# Super Admin Technical Operations Guide

1. Open **Technical Operations** and read the four separate conclusions.
2. Review `CRITICAL` and `WARNING` cards before optional-provider states.
3. Use **Run governed deep checks** only when bounded database/business evidence is required. It does not repair data.
4. Acknowledge or investigate an alert. Silence only a non-protected condition with a reason and expiry.
5. Create an incident when coordinated work/timeline ownership is needed; add only privacy-safe technical notes.
6. Plan maintenance with exact check keys. Start and complete/cancel it explicitly.
7. Use backup and restore runbooks outside the dashboard. Never treat file existence as proof.
8. Keep client policy advisory. Deployment and provider activation require separate authority.

If database integrity, migration, restore, or active-Super-Admin checks fail, stop risky changes and follow the linked runbook. Do not paste secrets, private records, screenshots with personal data, raw provider responses, or absolute paths into notes.
