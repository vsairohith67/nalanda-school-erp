# OBS Developer Guide

New checks must use a stable `checkKey`, one of the thirteen domains, bounded count-only evidence, a safe summary, retention, and an existing repository runbook. Never run network probes during page rendering. Reuse the owning module’s state table and provider profile rather than creating a parallel health system.

All write APIs require authentication, exact permission, same-origin request validation, JSON content type, bounded body size, POST semantics, no-store headers, and privacy-safe errors. State transitions require expected versions and append events. Automated repair, destructive restore, forced client refresh, and provider activation are prohibited.

Before release: migrate copied databases twice, exercise failure injection, restore logical backup twice, prove no duplicates or secrets, run role/mobile/theme Browser QA, then serialize routes, lifecycle, typecheck, tests, build, backup, and Git safety.
